# User Interface Design
In designing UniCab’s messaging, I began from the premise that a student should never have to learn how to chat, and for this reason I modeled the layout on the familiar texting app, placing one’s own messages on the right and the other person’s on the left, so that students arrive with a conceptual model already in place: one conversation per person, which they read from top to bottom, and which carries every update about their ride within the same timeline. Further, I wanted students to discover the state of the system at a glance; that is, the unread counts on the tab and on each inbox row, the ride pill that names the trip, and, once texting has closed, a lock note that reads “You can only message [user x] while you have a ride together” all tell the student what they can do before they attempt it. While the text field and send button act as the affordances for writing, the placeholder “Message Lynn,” the send/plane icon, and the car icon with its small count serve as their signifiers, and the mappings between them are direct, since the send button is text it sends and the number on the car matches the rides it opens. Importantly, I chose constraints that prevent errors rather than report them, so our UI keeps “Send” disabled for a blank text and for ride cancellation/rider removal, it holds the reason sheet’s button off until the student writes a real reason of 1 to 200 characters, which means the interface never invites what the database would refuse.
The chat also leans on the Gestalt principles of grouping, as the app gathers the messages that a student sends within fifteen minutes of each other under a single time label, and through proximity these messages read as one exchange rather than as scattered lines. Similarity, in turn, we gave each person’s bubbles one color and one side, so that a student can tell who wrote what without reading a single name, while the ride cards deliberately break that pattern, since I centered them, outlined them, and colored them green for an accepted ride or red for a cancelled one, so that they rise from the conversation as figure against ground. Coupled with the continuity of messages that flow from oldest to newest toward the text box, and the symmetry of bubbles that balance each other on either side of the screen, the design asks the student to recognize rather than recall, to reach the send button where the thumb already rests, as Fitts’s law suggests, and to trust that a message will appear the moment they send it.
I did consider other designs, the first of which would have kept the message box after a ride ended and shown an error once a student tried to send, but such a design hides the state of the system until the user has already acted, whereas the lock note makes the constraint discoverable from the start. Another, our original design opened one chat per ride, which scattered conversations with the same person across the inbox and, in doing so, broke the conceptual model that the layout use, so I changed the ratio to one chat per pair and added the rides-together icon at the top to let students see every ride they share. Finally, I considered showing ride updates as ordinary message bubbles, but these would have blended into the students’ own typed text, whereas message cards, through similarity in shape, read clearly as events in the ride’s story, and it is this clarity, I believe, that justified the current design.
